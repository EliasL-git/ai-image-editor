# AI Image Editor

An AI-native image editor: instead of manual masking, cloning and painting, you **select an object → describe the change → generate → keep editing**. Edits are non-destructive; every accepted generation creates a new version.

- **Frontend** — React + TypeScript + Fabric.js canvas, TailwindCSS, Zustand, TanStack Query (Vite)
- **Backend** — Node.js + Express + TypeScript (auth, uploads, job orchestration, projects/versions, export)
- **AI infra** — [Modal](https://modal.com) GPU services, each independently scaling; GPUs spin up on request and shut down when idle
  - **SAM 2** service — object selection / smart masking from brush/box/lasso hints
  - **FLUX.1 Kontext Dev** service — prompt + image + mask → edited image
- **Hosting** — [Render](https://render.com) blueprint (`render.yaml`): one web service for the app, one web service for the API, with a persistent disk for uploads/history

## Features

### MVP editing (all via natural language)
- Remove object · Replace object · Background replacement · AI fill · Color / clothing changes · Expand image · Relight image

### Selection system
- Brush, rectangle, ellipse, lasso — instant local mask previews
- **Magic Select** — your rough drawing is sent to SAM 2, which returns a precise object mask

### Non-destructive history
- Every accepted edit creates a new **version** (prompt, mask, image, parent link — Git-style)
- Restore any version, rewind, or branch a new edit from any point

### Export
- PNG / JPEG / WebP with full-resolution or canvas-resolution options

## Getting started (development)

Requires Node 20+.

```bash
npm install
cp .env.example .env        # fill in API values
npm run dev                 # runs web (:5173) + api (:8080) concurrently
```

Without Modal credentials, the API runs in **local fallback mode**: `/segment` returns a deterministic mask from your drawing and `/edit` returns the input image (watermarked) so the full canvas flow is testable offline.

## Deploying the Modal services

1. Install the Modal CLI and log in:
   ```bash
   pip install modal
   modal token new
   ```
2. Configure secrets (create in `modal secret create`):
   - `hf-token` — `HF_TOKEN` (Hugging Face read token)
   - `replicate-token` — `REPLICATE_API_TOKEN` (for the Kontext flux.1-kontext-dev model)
3. Deploy both services (models download once, then live on a shared Modal volume):
   ```bash
   npm run modal:deploy:sam
   npm run modal:deploy:flux
   ```
4. Copy the returned HTTPS endpoints (they look like `https://<workspace>--sam2-segment.modal.run` and `https://<workspace>--flux-kontext-edit.modal.run`) into the API env: `MODAL_SAM_URL`, `MODAL_FLUX_URL`.

## Deploying to Render

The repo includes a `render.yaml` blueprint. In the Render dashboard choose **New → Blueprint** and select this repository — it creates both services, the persistent disk, and the health checks automatically.

Service details:

| Service | Build | Start | Health |
| --- | --- | --- | --- |
| `ai-image-editor-web` | `npm ci && npm run build:web` | `npm run start:web` | `/health` |
| `ai-image-editor-api` | `npm ci && npm run build:api` | `npm run start:api` | `/health` |

Environment variables to set after the first deploy (blueprint marks them as required):
- Web service: `VITE_API_URL` → the API service's public URL, and `API_URL` → same
- API service: `MODAL_SAM_URL`, `MODAL_FLUX_URL` (from above), `CORS_ORIGIN` / `WEB_ORIGIN` → the web service's public URL, `API_INTERNAL_URL` → the API service's public URL
- `JWT_SECRET` is auto-generated by the blueprint

The web service serves the built SPA **and** proxies `/api/*` to the API service (using `API_INTERNAL_URL`), so everything can be served from one public origin if you prefer. `VITE_API_URL` is used by the client directly when set; both approaches work.

Uploads, history, and projects are stored on a 10 GB persistent disk mounted at `/var/data` (set `DATA_DIR`).

## API overview

```
POST /auth/register        create account (email + password)
POST /auth/login           get JWT
GET  /health               health check

POST /upload               upload an image → { id, url, width, height }
POST /segment              SAM 2 magic select: { imageId, mode, points/box/brush } → { jobId }
POST /edit                 FLUX edit: { imageId, prompt, mask, strength } → { jobId }
GET  /jobs/:id             poll job → { status, result? }

GET  /projects             list my projects
POST /projects             create project from an image
GET  /projects/:id         project + versions + history
POST /projects/:id/versions  restore a previous version as the new head

POST /export               render a version to PNG/JPEG/WebP
```

## How an edit flows

1. Upload an image → it loads onto the Fabric.js canvas
2. Draw over the object (brush / rectangle / ellipse / lasso) or use **Magic Select**
3. Magic Select sends the drawing to the SAM 2 service → precise object mask is returned and shown as an overlay
4. Type a prompt (e.g. "replace the red car with a vintage blue car")
5. Prompt + image + mask go to the FLUX Kontext service → preview appears in ~3–8 s (polling with live status)
6. **Accept** creates a new version; **Discard** keeps the previous state
7. Continue editing — history is a Git-like DAG you can always rewind

## Canvas layering

```
Result preview      (latest accepted/generated image)
Selection overlay   (SAM mask, dashed highlight)
Drawing layer       (user brush / lasso strokes)
Original image      (base fabric layer)
Background          (checkerboard)
```
